# 故障排查知识库（用户报错时的诊断依据）

## 诊断三条铁律（先读这个）

1. **用户面对的是打包好的应用，改不了程序**——永远不要建议用户改代码、改脚本、"等修复"。
2. **程序本身是能正常跑的**（已有用户在正常使用）——不要把问题归因为"可能是程序 bug"。
3. **用户跑不起来，100% 是配置的某个环节出了问题**：没配置好、没按教程做、或漏了步骤。诊断的目标永远是定位到"配置的哪一步漏了/错了"，并给出可操作的修复步骤。

## 诊断流程

1. 让用户把**完整的错误信息**（影刀报错文字/截图内容、或表格「发布任务提交时间」列里的错误信息）贴出来。
2. 运行 `diagnose`（怀疑附件问题时加 `--probe-media`），拿到自动体检结果。
3. 用下面的症状对照表 + 体检结果定位原因，用普通人能懂的话告诉用户：**哪一步配置出了问题 → 怎么改 → 改完怎么验证**。
4. 修复后重跑 `diagnose` 确认全绿，再让用户重试。

## 症状对照表

| 症状 / 错误特征 | 原因 | 解决 |
| --- | --- | --- |
| 影刀报"找不到字段/列/数据"，或写回失败 | 表格字段被改名或删除（RPA 按字段名取数） | 运行 schema-check，把字段名改回模板原名；类型被改的在表格里手动改回 |
| 影刀拉到一条数据就报错，表格里有半空的行 | 待发布队列里有空行/残缺行（RPA 拉取条件：发布任务提交时间为空且未勾选已发布，空行正好命中） | 运行 queue-check：残缺行补齐，空行确认后删除；以后用本 skill 上传就不会再产生 |
| 发布时打不开浏览器/找不到窗口 | ①「设置」表里该发布账号没填比特浏览器窗口ID；②笔记里的发布账号和「设置」表里的名字不一致（多个空格都算不一致）；③比特浏览器没开或窗口ID变了 | 核对「设置」表：账号名逐字一致、窗口ID 从比特浏览器复制最新的；发布前确认比特浏览器在运行 |
| 接口报错 code 非 0（授权/权限类），或 skill 连不上表格 | config.json 里的授权码（auth_code）失效、被重置，或对这张表没有编辑权限 | 打开多维表格重新生成 pt- 授权码，更新 config.json；用 check-config 验证 |
| skill 提示 CONFIG_NOT_FOUND | config.json 不在默认位置（桌面\影刀文件夹\小红书发布\图文发布\），或内容格式不对 | 引导用户提供 table_url + auth_code，用 save-config 保存 |
| 到点没发布 | 定时发布用的是**电脑系统定时**，不是小红书官方定时 | 确认到点时电脑开着、影刀应用在运行、比特浏览器可用 |
| 发布失败且标题相关 | 标题超过 20 字符 | 改短标题（本 skill 上传会拦住这种情况） |
| 发出来的笔记标签是一坨/一个标签里塞了很多 | 标签字段一个选项塞了多个标签 | 运行 clean-tags 清理；以后一个标签一个选项（带不带 # 都行） |
| 封面/图片顺序不对 | 图片按**文件名**从小到大排序，最小的是封面（图1.jpg 在 图2.jpg 前面） | 按想要的顺序重命名图片；用本 skill 上传会自动处理 |
| 图片/视频没传上 | 单文件超 20MB 走了 fallback，或用户忘了手动拖图 | 压缩文件重传，或把文件拖进该行「封面及配图」单元格 |
| 笔记类型是"长文/文字配图"的行发不出去 | RPA 目前只支持 图文、视频 | 把笔记类型改成 图文 或 视频 |
